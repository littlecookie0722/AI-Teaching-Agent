# cli

Phase 1 的 `lab-cli` Mock 实现。该模块只做本地 DSL、状态流转和统一 JSON 返回验证，不调用真实大模型、真实后端或真实云资源。

> 当前没有真实实训平台后端接口。`platform-entity import-send`、`platform-entity import-status`、真实平台 draft import、平台状态查询、平台侧签收和 `AGENT_API_TOKEN` 均为未来其他团队对接项；当前默认只执行本地闭环：真实 LLM 生成 DSL、Schema 校验、人工审核、本地 import-preview、mock-import、import-dry-run DTO、受控评分 evidence 和本地评分记录复核。

## 输入说明

- Markdown 输入：如 `examples/input/demo-source.md`。
- 无 Key 离线 Demo：`demo offline`，默认输入为 `examples/input/demo-source.md`，可通过 `--output`、`--workflow-output` 和 `--candidate-preview-output` 指定三个 JSON 产物路径。
- 素材分析输入：本地 `.md`、`.markdown`、`.txt`、`.sh`、`.bash` 文件，最大 256KB。
- DSL 输入：如 `templates/grading/examples/python-pytest.yaml`。
- AI Task Mock 存储：源码 checkout 默认兼容写入 `cli/.lab_cli_store.json`；安装 wheel 后默认写入用户工作区的 `.lab_cli_store.json`。可通过 `LAB_CLI_WORKSPACE` 指定工作区，或通过 `LAB_CLI_STORE` 指定完整 JSON 文件路径；`workspace info` 可只读查看最终路径。
- 安装式 Lab Golden Path：在空目录中运行 `ai-teaching-agent lab generate-from-source --input source.md`，产物写入用户工作区并保持 `WAITING_REVIEW`；人工 `review approve` 后可继续 `lab import-preview`，不会写入 `site-packages`、自动发布或调用真实平台。
- 安装式 PPTX Artifact：安装 wheel 后，`ppt artifact build` 的临时构建目录、PPTX、manifest 和预览文件都写入用户工作区，不写入 `site-packages`；需要 Node.js 和可发现的 presentations runtime。
- Artifact Mock 清单同样写入本地 Mock store，不连接对象存储或远程文件服务。
- Backend Core PostgreSQL 测试库迁移输入为 `LAB_BACKEND_CORE_DATABASE_URL` 或自定义 `--database-url-env` 指向的 `postgresql://...` URL；命令只返回脱敏摘要，不回显 host、账号、密码或完整连接串。
- Quality 回归测试矩阵输入为固定 `profile`：`quick`、`core`、`backend-core`、`real-llm-offline`、`mcp`；不接受任意命令字符串。
- 审核详情输入为本地 AI Task id，用于聚合任务、产物、Workflow、审计和发布策略。
- 审核批量摘要输入为状态、任务类型和可选 limit，只做队列查看，不做批量状态变更。
- Provider Runtime Guard 输入为真实 Provider 占位 id、Prompt 范围、timeout、retry、concurrency 和可选 JSON payload；payload 只用于本地脱敏预览。
- Real LLM dry-run plan 输入为真实 Provider 占位 id、Prompt 范围、timeout、retry、concurrency 和可选 JSON payload；payload 只用于本地脱敏预览，不检查密钥是否存在。
- Real LLM approval gate 输入为真实 Provider 占位 id、审批编号、审核人和本地确认项；只评估真实 SDK 实现任务前的批准清单，不授权真实调用。
- Real LLM SDK task blueprint 输入为真实 Provider 占位 id、审批编号、审核人、本地确认项、模型别名和可选 JSON payload；只生成未来实现任务蓝图，不安装 SDK、不改契约、不检查密钥、不访问网络。
- Real Provider SDK PoC harness 输入为真实 Provider 占位 id、审批编号、审核人、本地确认项、显式 opt-in 和可选 JSON payload；只验证默认禁用门禁，不安装 SDK、不导入 SDK、不检查密钥、不联网。
- Real SDK enablement 输入为真实 Provider 占位 id、审批编号、审核人、蓝图确认项、SDK 依赖审查、Provider/Runtime 契约审查、密钥注入审查、网络审查和回滚确认；只评估最终开关设计，不修改契约、不授权真实调用。
- Real SDK minimal implementation shell 输入为 `openai`、审批编号、审核人、enablement 确认项、显式 implementation opt-in 和可选 JSON payload；只验证默认禁用实现外壳，不导入 SDK、不创建客户端、不检查密钥、不联网。
- Real SDK dependency/env gate 输入为 `openai`、审批编号、审核人、enablement 确认项、SDK 包名/版本/license/hash/env/CI 确认项和可选 JSON payload；只评估未来依赖安装任务门禁，不安装 SDK、不检查密钥、不联网。
- Real SDK dependency install plan 输入为 `openai`、审批编号、审核人、dependency/env gate 确认项、package manager、lockfile、版本 pin、hash 校验、回滚文件、CI cache 和安全策略确认项；只评估未来依赖安装计划草案，不生成安装命令、不安装 SDK、不解析包版本或 hash、不改 lockfile。
- Real SDK dependency installer audit 输入为 `openai`、审批编号、审核人、install plan 确认项、命令审查、依赖文件审查、lockfile diff 审查、离线 CI 审查、回滚命令审查和禁用执行确认；只评估未来安装执行壳任务，不物化命令、不安装 SDK、不改文件、不解析包、不检查密钥、不联网。
- Real SDK dependency change preview 输入为 `openai`、审批编号、审核人、installer audit 确认项、manifest/lockfile/rollback 预览确认项和可选 JSON payload；只评估未来依赖文件变更预览任务，不写文件、不生成 diff、不安装 SDK、不解析包、不检查密钥、不联网。
- Real SDK dependency patch proposal 输入为 `openai`、审批编号、审核人、change preview 确认项、patch scope、patch plan、禁止写 patch、禁止 apply、禁止 diff artifact 确认项和可选 JSON payload；只评估未来补丁任务，不写 patch、不应用补丁、不写依赖文件、不生成 diff artifact。
- Real SDK dependency apply gate 输入为 `openai`、审批编号、审核人、patch proposal 确认项、apply scope、最终人工批准、备份、回滚演练、禁止 apply、禁止写依赖文件、禁止执行命令确认项和可选 JSON payload；只评估未来补丁应用任务，不授权 apply、不写文件、不执行命令。
- Real SDK dependency content read approval 输入为 `openai`、审批编号、审核人、readonly snapshot 确认项、内容读取审批范围、读取理由、脱敏策略、manifest/lockfile 内容读取策略、禁止本轮读取、禁止持久化、禁止 patch、禁止命令执行、禁止依赖安装和禁止真实调用确认项；只生成未来依赖文件内容读取审批模型，不读取依赖文件内容。
- Real SDK dependency content read plan 输入为 `openai`、审批编号、审核人、content read approval 确认项、读取计划范围、目标审查、manifest/lockfile 读取窗口、脱敏测试计划、审核人分配、禁止本轮读取、禁止返回原文、禁止写内容 snapshot、禁止写计划产物、禁止 patch、禁止命令执行、禁止依赖安装和禁止真实调用确认项；只生成未来依赖文件内容读取只读审查计划，不读取依赖文件内容。
- Real SDK dependency content read final confirmation 输入为 `openai`、审批编号、审核人、content read plan 确认项、最终读取范围、最终批准人、工单、目标确认、manifest/lockfile 最终确认、脱敏策略、禁止返回原文、禁止持久化、禁止写确认产物、禁止 patch、禁止命令执行、禁止依赖安装和禁止真实调用确认项；只生成未来真实只读读取任务前的最终确认模型，不读取依赖文件内容。
- Real SDK dependency content read readonly execution 输入为 `openai`、审批编号、审核人、final confirmation 确认项、只读读取范围、执行批准人、执行工单、manifest/lockfile 读取确认、返回前脱敏确认和禁止原文返回、禁止持久化、禁止写产物、禁止 patch、禁止命令执行、禁止依赖安装、禁止密钥检查、禁止联网、禁止真实调用确认项；只读取允许名单内本地依赖文件并返回脱敏预览。
- Real LLM SDK boundary 输入为 `openai`、显式 boundary opt-in 和可选密钥环境变量存在性检查；只确认 `requirements.txt` 是否声明 `openai`、本地 SDK 包元数据是否可解析、`OPENAI_API_KEY` 环境变量名是否存在，不导入 SDK、不创建客户端、不读取或输出密钥值、不联网、不真实调用。
- Real LLM runtime config 输入为 `provider real-llm-runtime-config`；只读汇总 `OPENAI_API_KEY` 是否存在、`OPENAI_MODEL` 值和 `OPENAI_BASE_URL` 的来源/脱敏摘要，命令模板中的 endpoint 主机使用占位符，不返回 API Key 值、不导入 SDK、不创建 client、不发请求。
- Real LLM minimal PoC 输入为 `openai`、本地输入材料、输出路径、`--model` 或 `OPENAI_MODEL`、真实 `OPENAI_API_KEY` 和显式确认项；只发送一次真实请求，生成 Lab DSL，校验通过后创建 `WAITING_REVIEW` AI Task。
- Phase 2 Workflow 真实 Lab 回接输入为 `phase2 workflow run --provider-mode real-llm-minimal`、本地素材、真实 Lab 输出路径、`--model` 或 `OPENAI_MODEL`、真实 `OPENAI_API_KEY` 和显式确认项；只让 Lab DSL 使用真实 LLM，Exam / Grading / PPT 仍走 MockProvider。
- Phase 2 Workflow 真实 LLM 输入为 `phase2 workflow run --provider-mode real-llm`、本地素材、四类 DSL 输出路径、`--model` 或 `OPENAI_MODEL`、真实 `OPENAI_API_KEY` 和显式确认项；可通过 `OPENAI_BASE_URL` 指向 OpenAI-compatible endpoint。Lab / Exam / Grading / PPT 默认各发起一次真实 LLM 请求，输出仍全部进入 `WAITING_REVIEW`。可选 `--api-surface chat.completions` 可直接绕过 Responses API；可选 `--repair-on-schema-failure` 会在某一类 DSL Schema 校验失败时最多追加一次真实修复请求，报告中通过 `provider.requestCount`、`schemaRepairAttempted`、`schemaRepairApplied` 和 `schemaRepair` 标记。真实 LLM 响应会先拆掉 Markdown `json` code fence、单元素数组根节点和常见 `dsl` / `data` / `result` / `*Dsl` envelope，再进入本地归一化和 Schema 校验。真实 Lab DSL 会对 `difficulty`、`durationMinutes`、`tags`、`objectives`、`targetUsers`、`materials`、`environment.resources` 和步骤字段漂移做本地归一化；真实 Exam DSL 会对 `questionType` 同义词、`totalScore` 字符串和题目 `score` 漂移做本地归一化，并保持题目分值合计等于总分；真实 PPT DSL 会对 slide type 同义词、bullets 形态、speaker notes 和时长字段做本地归一化，把可审核信息保留在 slide bullets 中。每类 `generatedDsl.<kind>.qualitySummary` 会汇总 Provider / Schema 层质量，例如 `readyForReview`、归一化 patch 数、Schema 修复状态、请求次数、API surface 和 response id；`generatedDsl.<kind>.contentQualitySummary` 与报告级 `contentQualitySummary` 会汇总 DSL 内容层质量，例如目标/步骤数量、题目分值、gradingRef 覆盖、assessmentPlan 对齐、PPT 页数和是否可进入导入预览，并通过 `decisionStatus`、`recommendedAction`、`requiresRevisionBeforeImportPreview`、`requiresEvidenceBeforeFinalApproval`、`blockers`、`warnings` 输出人工审核下一步建议。这些决策字段不自动审核、不自动发布。
- Phase 2 Workflow 真实 Demo 输入为 `phase2 workflow run --provider-mode real-llm-demo`，仅作为历史演示入口保留；后续真实内容生成默认使用 `real-llm`。
- 教学包本地导出输入为已有 `teaching-core` WorkflowRun、导出审核人和可选 ZIP 路径：`teaching-package export --workflow-run-id <id> --reviewer <name> [--output <zip>]`。命令要求 Lab / Exam / Grading 三项均为 `APPROVED`，重新执行 DSL Schema 与候选预览脱敏校验，然后原子写出固定六成员 ZIP；默认路径为 `examples/output/teaching-packages/<workflowRunId>.zip`。未全部批准或校验失败时不写部分包，不改变任务状态、不调用平台实体、不执行评分、不发布。
- Phase 2 真实 Demo 演示包输入为已有真实 Workflow Report、四类真实 DSL、本地提交目录和演示包输出路径：`phase2 demo-bundle build`；命令只复放已有产物并做本地收口，不新增 LLM 请求、不读取密钥、不访问网络。命令会额外生成独立的只读 evidence 演示 Grading DSL 和报告，用于展示 `file_exists` / `json_field` / 静态 `notebook_cell` 评分证据，不修改原始真实 LLM Grading；同时从 PPT DSL 生成待审核 PPTX Artifact 附件。
- PPTX Artifact PoC 输入为本地 `WAITING_REVIEW` PPT DSL：`ppt artifact build --dsl templates/ppt/examples/course-ppt.yaml`；命令使用 bundled artifact-tool 导出本地 `.pptx`，写入 `PPTX_FILE` Artifact，仍需人工审核，不新增 LLM 请求、不读取密钥、不自动发布。
- Exam 候选人预览输入为本地 Exam DSL：`exam candidate-preview --exam templates/exam/examples/notebook-fill-blank.yaml`；命令会先执行 Exam Schema 校验，再导出不含标准答案字段和答案文本的选手端 JSON。
- 真实 DSL 审核预览输入为本地 Lab / Exam / Grading / PPT DSL 和候选人预览：`review real-dsl-preview`；命令确定性生成 `RealDslReviewPreview`，把真实 DSL 内容整理为审核页可读摘要，并输出 `qualitySignals`、`reviewIssues`、`revisionSuggestions`，帮助审核人决定下一步修订；不新增 LLM 请求、不读取密钥、不执行命令、不创建任务、不发布。
- 真实 DSL 修订草稿输入为本地真实 DSL、审核人和修改意见：`review real-dsl-revision`；默认 `--provider-mode local` 生成确定性本地 `WAITING_REVIEW` 修订 DSL 与 revision report，不新增 LLM 请求、不读取密钥、不访问网络、不自动通过、不发布。显式传 `--provider-mode real-llm`、`--explicit-real-call-opt-in`、`--confirm-waiting-review`、`--confirm-no-auto-publish` 后，会复用 OpenAI-compatible SDK 发起一次真实二次修订请求；模型可来自 `--model` 或 `OPENAI_MODEL`，base URL 可来自 `--base-url` 或 `OPENAI_BASE_URL`，输出仍为 `WAITING_REVIEW` DSL。
- 真实 DSL 批量修订草稿输入为 `RealDslReviewPreview` 文件：`review real-dsl-revision-batch`；命令读取 `revisionSuggestions`，按 kind 生成多份本地 `WAITING_REVIEW` 修订 DSL 与批量 report，不新增 LLM 请求、不读取密钥、不访问网络、不自动通过、不发布。
- 真实 DSL 修订差异预览输入为 `RealDslRevisionBatch` 报告：`review real-dsl-revision-diff-preview`；命令读取源 DSL 与修订 DSL，输出 `RealDslRevisionDiffPreview`，列出每个草稿的 changed fields、源值摘要、修订值摘要、`allDraftsWaitingReview` 与发布阻断状态；不新增 LLM 请求、不读取密钥、不访问网络、不自动通过、不发布。
- 平台实体导入预览输入为已审核通过的 DSL 任务：`lab import-preview`、`exam import-preview`、`grade import-preview` 分别读取任务关联的 `LAB_DSL`、`EXAM_DSL`、`GRADING_DSL` Artifact，重新执行 Schema 校验，生成本地 `LabTemplateImportPreview`、`ExamQuestionImportPreview` 或 `GradingRuleImportPreview` 和 `WORKFLOW_REPORT` Artifact，并写入对应操作审计。它们只生成平台 `lab_template`、`exam_question`、`grading_rule` 草稿预览，固定 `databaseWritten=false`、`realPlatformImport=false`、`realPublishAllowed=false`，不会写真实数据库、调用平台导入 API 或发布。`GradingRuleImportPreview` 会额外返回 `controlledEvidenceNextAction`，指向 `POST /api/grading/evidence-auto` 与 `grade evidence-auto --include-controlled-command`，用于提示最终导入复核前先生成受控评分 evidence；导入预览本身不运行沙箱、不执行选手代码。预览生成并人工确认后，可用 `lab mock-import`、`exam mock-import`、`grade mock-import` 将草稿写入本地 JSON store 的 `platformEntities`，再通过 `platform-entity list/get` 查询；`platform-entity readiness-report` 会只读汇总三类实体是否已生成导入预览、是否已 Mock 入库、是否可进入人工平台复核，并在 `grading_rule` item 的 `gradingRecordReviewEvidence` 中显示最新 `GradingRecord` 是否已人工 `record-review approve-ready`，汇总计数为 `gradingRecordReviewApplicableTotal`、`gradingRecordReviewReadyTotal`、`gradingRecordReviewBlockedTotal`。该 evidence 只辅助平台复核，不改变导入预览 ready 语义，不自动签收或发布。该步骤仅 `mockStoreWritten=true`，仍保持 `databaseWritten=false`、`realPlatformImport=false`、`realPublish=false`。
- 平台实体本地 dry-run 输入为 `AgentEntityImportDryRun` 报告：`platform-entity import-dry-run --contract-config <json>` 可用本地 JSON 覆盖未来平台字段差异，包括 `entities.<entityType>.draftImportPath`、`statusPathTemplate`、`draftIdResponseKeys`、`statusResponseKeys`、`statusMapping` 和 `requestBodyMapping`；dry-run 只生成本地 DTO、目标 endpoint 预览和契约校验结果，固定不读取平台 token、不发送 HTTP、不写真实平台。`platform-entity import-send` 和 `platform-entity import-status` 仅保留为未来对接团队技术参考，当前默认不得作为下一步执行。
- Phase 2 Workflow Lab 生成业务参数包括 `--target-users`、`--duration-minutes`、`--difficulty`、`--tech-tags` 和 `--teaching-style`；输出会在 Report、Lab Artifact metadata 和 Review Detail 中记录 generation context、quality signals、review highlights 和 provider summary。
- Phase 2 Grading 生成输入为 `phase2 grading-generate run --exam templates/exam/examples/notebook-fill-blank.yaml`；只读取本地 Exam DSL，通过 MockProvider 生成 Grading DSL 审核包，输出 `assessmentPlan`、coverage 和 explainability 质量信号。
- 真实沙箱前评分预检输入为本地 Grading DSL：`grade sandbox-precheck --grading templates/grading/examples/mixed-checks.yaml`；命令复用 GradingRunner 的计划报告，检查 assessmentPlan、sandboxExecutionRequest、containerSandboxPlan 和资源限制是否足够清楚，不执行真实沙箱或选手代码。
- 只读沙箱 PoC 输入为本地 Grading DSL 和提交目录：`grade sandbox-run --grading templates/grading/examples/readonly-sandbox.yaml --submission examples/submissions/readonly-demo`；当前执行 `file_exists`、`json_field`、静态 `notebook_cell` `.ipynb` JSON 解析和 `log_keyword` UTF-8 文本扫描，`stdout_contains` / `pytest` deferred，不执行命令、pytest、Notebook kernel 或选手代码；输出包含统一 `reportDetail`，可直接被评分报告页、审计和演示包复用。
- 受控 Docker 命令沙箱 PoC 输入为本地 Grading DSL、提交目录和显式执行模式：`grade sandbox-run --execution-mode controlled-command --grading templates/grading/examples/controlled-command-sandbox.yaml --submission examples/submissions/controlled-command-demo --image <local-python-image>`；只支持 `stdout_contains` 和 `pytest`，提交目录只读挂载、网络关闭，不自动拉取镜像，不执行 Notebook、未知 Shell、宿主机命令或真实发布。报告会返回 `imageSupplyChain`，记录本地 `docker image inspect` 的 imageId/digest、allowlist 匹配、禁止自动 pull 和未使用 registry auth；当前为本地 PoC 审计模式，不等同生产镜像签名强校验。
- 评分 evidence 合并输入为多份已有本地评分报告：`grade evidence-merge --report examples/output/readonly-sandbox-report.json --report examples/output/controlled-command-sandbox-report.json --output examples/output/merged-evidence-report.json`；如需在审核详情中展示合并覆盖率，可额外传 `--task-id <grading-task-id>` 将 `GRADING_EVIDENCE_MERGE` Artifact 归属到对应 Grading 审核任务。命令只读取已有 JSON 报告并按 check id 合并 `reportDetail.checkPlans`，不读取 submission、不启动 Docker、不执行命令、不调用真实 LLM、不自动通过或发布。
- 评分 evidence 就绪摘要输入为一到多份已有本地评分报告：`grade evidence-readiness --report examples/output/merged-evidence-report.json --output examples/output/grading-evidence-readiness.json`；输出 `GradingEvidenceReadiness`，列出已就绪 check、缺失 evidence、建议下一步只读/受控 evidence 或人工复核动作。该命令只读已有报告，不启动 Docker、不执行 pytest、不启动 Notebook、不执行选手代码。
- 自动评分 evidence 编排输入为 Grading DSL 和提交目录：`grade evidence-auto --grading templates/grading/examples/mixed-checks.yaml --submission examples/submissions/readonly-demo --output examples/output/grading-evidence-auto.json`。默认只运行只读 evidence 并输出合并报告；显式传 `--include-controlled-command` 后才会尝试受控 Docker `stdout_contains` / `pytest` 证据，Docker 或镜像不可用时默认降级为只读报告并记录 warning，不会在宿主机执行命令。`executionMatrix.items` 会在每个 check 顶层直接给出 `status`、`passed`、`earnedScore`、`evidenceSourceKind`、`exitCode`、`stdoutTail`、`stderrTail`、`filesInspected`、`errorCode` 和 `errorReason`，供审核页、评分报告页和命令行快速定位失败原因。

- 真实 LLM Demo Grading DSL 归一化输入为本地 Grading DSL 和可选 Exam DSL：`grade normalize --grading examples/output/real-llm-grading.json --exam examples/output/real-llm-exam.json --output examples/output/real-llm-demo-grading-normalized.json`；命令只做本地确定性字段补齐、check type 同义词归一化和 Schema 校验，不重新调用真实 LLM。
- Real LLM PoC Adapter 输入为真实 Provider 占位 id、Prompt 范围、timeout、retry、concurrency、显式 opt-in 和可选 JSON payload；当前只串联本地门禁并安全失败。
- `review detail --output` 可把聚合详情导出为本地 JSON，建议写入 `examples/output/`，该目录下生成 JSON 默认不进入版本库。
- `review core-readiness --task-id <task_id>` 只读聚合 `review detail`、内容质量摘要、平台实体 readiness 和 Grading `preApproveReviewCheck`，输出 `CoreWorkflowReadinessReport`，用于判断某个任务离本地核心演示闭环还缺哪一步。Lab 任务只检查 `lab_template`，Exam 组合任务检查 `exam_question` 与 `grading_rule`，Grading / Grading 修订任务检查 `grading_rule` 并额外检查 evidence、decision note 和 `approve-ready` 决策；PPT 任务只检查 `ppt_deck`。已完成 `import-preview -> mock-import -> import-dry-run` 后，报告固定返回 `recommendedNextAction=LOCAL_CORE_MVP_STOP_LINE_REACHED` 和同名 `reasonCode`，不建议 `import-send`、`import-status`、平台签收或最终发布。没有评分记录时不会阻断 Grading DSL 导入预览，但已有评分记录且尚未复核通过时会在 `nextToolRecommendation` 中给出 `grade record-review` 人工 CLI 建议，且 `toolAvailable=false`。当 `contentQualitySummary` 判定 `NEEDS_REVISION_BEFORE_IMPORT_PREVIEW` 时，`recommendedNextAction` 会优先指向 `review revision-request`。该命令不执行导入、不发送请求、不启动沙箱、不自动 approve、不发布。

  平台真实请求相关工具可能在历史推荐参数里保留 `<reviewed_dry_run_report_path>`、`<platform_api_base_url>`、`<reviewed_import_send_report_path>` 等占位符；默认 `local-core-mvp` profile 会在 import-dry-run 后以 `LOCAL_CORE_MVP_STOP_LINE_REACHED` 停止。`--profile all` 仅用于历史全量 manifest 回归参考，不作为当前本地核心闭环默认路线。

## 限制说明

- 仅 Phase 1 Mock，不发布真实实验、考试或评分。
- `phase1 check` 会使用临时本地文件完成自检，不写入真实资源。
- `phase1 export` 只导出本地 Mock 交付包，不发布真实内容；交付包包含 `deliveryManifest`、`acceptanceChecklist`、`acceptanceSummary` 和 `safetyAssertions`。
- `phase1 report` 只读取本地 Mock 交付包并生成 Markdown 验收报告，不重新生成内容、不调用真实 Provider、不发布真实内容。
- `provider real-sdk-dependency-env check` 只返回统一 JSON 设计评审结果；`readyForDependencyImplementationTask=true` 不等于安装 SDK 或允许读取密钥。
- `provider real-sdk-dependency-install-plan plan` 只返回统一 JSON 计划草案；`readyForDependencyInstallImplementationReview=true` 不等于生成安装命令、安装 SDK、解析包版本或 hash、修改 lockfile、检查密钥或联网。
- `material analyze` 只做本地静态摘要和风险识别，固定 `realLlmCalled=false`、`remoteContentFetched=false`、`unknownShellExecuted=false`、`sandboxExecuted=false`。
- `lab generate-from-source` 会先复用素材分析结果，再返回本地 Lab DSL 示例并创建 `WAITING_REVIEW` 任务。
